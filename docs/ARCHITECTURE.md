# Устройство сервиса

## Стек

| Слой | Технологии |
|---|---|
| Бэкенд | FastAPI, Pydantic v2, SQLAlchemy 2, Alembic |
| Очередь задач | Celery + Redis, очереди `collect` и `analyze` |
| Хранение | PostgreSQL 16 + PostGIS, MinIO |
| Спутник | Google Earth Engine, Sentinel-2 и Sentinel-1 |
| Погода | Open-Meteo: архив ERA5 и прогноз на 14 дней |
| Контуры | OpenStreetMap / Overpass API |
| Восстановление пропусков | CatBoost, модель V6 |
| LLM | OpenRouter, только пересказ проверенных расчётов |
| Отчёты | WeasyPrint, Jinja2, matplotlib |
| Фронтенд | React 18, TypeScript, Vite, Tailwind, Radix UI |
| Карта и графики | Leaflet, leaflet-geoman, ECharts |
| Окружение | Docker Compose |

## Сервисы

```
api              FastAPI: REST и поток прогресса SSE, долгих операций не выполняет
worker-collect   Celery: GEE и Open-Meteo, упирается в сеть
worker-analyze   Celery: климатология, аномалии, риск, отчёты, упирается в CPU
postgres         PostGIS: полигоны, наблюдения, аномалии, прогнозы
redis            брокер Celery, кэш внешних API, шина прогресса
minio            PDF-отчёты, превью снимков, кэш растров
web              nginx: раздача SPA и проксирование /api
migrate          одноразовый шаг миграций
```

Миграции вынесены отдельным шагом, а не в старт приложения: несколько реплик API накатывали бы их наперегонки.

## Сущности

**Поле** — контур, временной ряд, аномалии, балл риска. Расчёт идёт по полю.

**Проект** — рабочее пространство с общим периодом наблюдения. Период общий, чтобы поля были сопоставимы при ранжировании.

**Хозяйство** — сельхозпроизводитель, которому принадлежат поля. Справочник общий и проекту не принадлежит: название, ИНН и район от периода не зависят. Заведённое однажды хозяйство доступно из любого проекта.

Заключение по хозяйству считается внутри проекта: от периода зависит не хозяйство, а оценка. Реестр ранжирует только те хозяйства, у которых есть поля в этом проекте, — у всех полей проекта период общий.

## Индекс потребности в поддержке

Средневзвешенный по площади риск полей хозяйства плюс надбавки за долю критической и проблемной площади. Не хранится, считается на чтении по строкам полей.

Три правила, определяющие его поведение:

**Веса поля не пересчитываются.** Индекс строится поверх готовых баллов полей. Иначе прогноз ухудшения вошёл бы в сумму дважды — он выведен из тех же отклонений, что и уже учтённая текущая динамика.

**Поля без наблюдений в средневзвешенное не входят.** Их площадь выносится отдельным показателем и понижает достоверность, а не балл. Иначе хозяйство, про которое нечего сказать, оказалось бы внизу реестра — то есть система заявила бы «поддержка не нужна» там, где просто ничего не увидела.

**Итог не опускается ниже 0,6 максимального балла отдельного поля.** Средневзвешенное по площади врёт одним способом: поле в 20 га с баллом 85 на хозяйстве в 800 га даёт вклад в два балла и исчезает.

Достоверность выводится всегда рядом с баллом. Порознь они позволяют прочитать «низкая потребность» там, где на хозяйство просто нет снимков.

## Модель восстановления пропусков

Пропуски NDVI восстанавливает **V6**: CatBoost предсказывает поправку к линейной опоре, приведённой к шкале конкретного прибора, предсказания трёх приборов сворачиваются вероятностями классификатора съёмки. Подробно — [`backend/agropulse/ml/v6/README.md`](../backend/agropulse/ml/v6/README.md).

Модель обучена заранее, артефакты в репозитории. Обучение в сервисе не запускается никогда. Один клиент обслуживает и веб-сценарий, и batch-инференс.

Прогноз вперёд V6 не делает — она восстанавливает точку между наблюдениями. Прогноз считает климатический метод (`ml/climatology_forecast.py`), его источник показывается пользователю отдельно.

Запасной путь — внешний сервис моделей по контракту [`ML_API.md`](ML_API.md), включается при `ML_V6_ENABLED=false`.

## Структура репозитория

```
backend/
  agropulse/
    main.py            точка входа FastAPI
    config.py          настройки, только из переменных окружения
    db/                модели SQLAlchemy и подключение
    api/routers/       HTTP-эндпоинты
    providers/         внешние источники за общими интерфейсами
    features/          построение признаков для модели
    ml/                модель V6, клиент ML-сервиса, baseline
    analytics/         климатология, аномалии, риск, индекс хозяйства
    llm/               пояснения через OpenRouter
    reports/           CSV и PDF
    storage/           объектное хранилище
    tasks/             задачи Celery
    cli.py             batch-инференс
  migrations/          Alembic
  tests/               модульные и интеграционные
frontend/
  src/
    api/               клиент REST и подписка на поток прогресса
    app/               оболочка проекта и общий контекст
    components/        карта, графики, примитивы
    pages/             экраны сценария
    lib/               форматирование, статусы, разбор ряда
  nginx.conf.template  раздача SPA и проксирование /api
scripts/               проверка GEE и внешних API
docs/                  план, контракт с ML-сервисом, исследование
data/                  обмен файлами для batch-инференса
secrets/               ключ сервис-аккаунта GEE
```
