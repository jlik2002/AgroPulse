# Хозяйства и реестр поддержки

Решение о государственной поддержке принимается по хозяйству целиком, а не по отдельному контуру. Отсюда второй уровень выводов над полем.

## Справочник общий

Хозяйство проекту не принадлежит: название, ИНН и район предприятия от периода наблюдения не зависят. Заведённое однажды доступно из любого проекта.

От периода зависит не хозяйство, а заключение по нему. Поэтому сравнимость сохраняется в другом месте: реестр строится по проекту и ранжирует только те хозяйства, у которых есть поля в этом проекте, — а у всех полей проекта период общий.

Отсюда адресация: справочник плоский (`/api/farms`), заключение вложено (`/api/projects/{id}/farms/{id}/summary`).

Хозяйство обязательно при создании поля через API, но колонка `farm_id` остаётся nullable: полям, заведённым до появления хозяйств, выдуманный владелец не приписан. Они видны отдельной группой «поля вне хозяйств», а не спрятаны.

Удаление хозяйства снимает ссылку через `ON DELETE SET NULL` и поля не трогает: вместе с ними ушли бы собранные наблюдения.

## Индекс потребности в поддержке

```
оценённые поля     = статус critical | attention | normal, балл есть
base               = Σ(площадь × балл) / Σ площадь по оценённым
critical_share     = площадь критических / оценённая площадь
problem_share      = площадь (critical + attention) / оценённая площадь

composite          = base + 15 × critical_share + 10 × problem_share
индекс             = min(100, max(composite, 0.6 × максимальный балл поля))
```

Три решения определяют его поведение.

**Веса поля не пересчитываются.** Индекс строится поверх готовых баллов полей. Иначе прогноз ухудшения вошёл бы в сумму дважды: он выведен из тех же отклонений, что и уже учтённая текущая динамика.

**Поля без наблюдений в средневзвешенное не входят.** Их площадь выносится отдельным показателем и понижает достоверность, а не балл. Иначе хозяйство, про которое нечего сказать, оказалось бы внизу реестра — то есть система заявила бы «поддержка не нужна» там, где просто ничего не увидела.

**Итог не опускается ниже 0,6 максимального балла отдельного поля.** Средневзвешенное по площади врёт ровно одним способом: поле в 20 га с баллом 85 на хозяйстве в 800 га даёт вклад в два балла и исчезает. Одно поле в критическом состоянии — уже основание для проверки.

Индекс нигде не хранится, считается на чтении по строкам полей. Третьего места, где данные протухают, не появляется.

## Достоверность

Выводится всегда рядом с баллом. Порознь они позволяют прочитать «низкая потребность» там, где на хозяйство просто нет снимков.

| Уровень | Условие |
|---|---|
| Высокое | оценено ≥ 80 % площади и средняя уверенность ≥ 0,6 |
| Среднее | оценено ≥ 50 % площади и средняя уверенность ≥ 0,35 |
| Низкое | иначе |

Если оценено меньше половины площади, заключение не выдаётся вовсе.

## Категории для комиссии

| Категория | Ситуация | Действие |
|---|---|---|
| Срочная проверка | индекс ≥ 60, отклонения не оспорены | рассмотреть первоочередно |
| Рассмотреть поддержку | индекс ≥ 30 | наблюдение и рассмотрение |
| Запросить сведения | отклонения не подтверждаются | дополнительная проверка |
| Плановое наблюдение | индекс < 30 | в экстренную очередь не включать |
| Уточнить данные | заключения нет | решение без проверки не менять |

Ни одна формулировка не назначает выплату. Спутник видит угнетение растительности, а не основание для платежа: система даёт основание рассмотреть хозяйство, распоряжается комиссия.

## Реестр

Три списка, а не один отсортированный:

1. **Очередь рассмотрения** — хозяйства с заключением, по убыванию индекса.
2. **Без заключения** — данных не хватает. В конец очереди их ставить нельзя: последнее место читается как «поддержка не нужна».
3. **Хозяйства без полей в этом проекте** — есть в справочнике, оценивать здесь нечем.

Отдельно перечисляются поля вне хозяйств: их площадь документом не покрыта, и это видно, а не спрятано.

## Демонстрационные данные

Миграция `c7f3e91a4b58` заполняет справочник пятью организациями с реквизитами: на пустой базе поле нельзя завести вовсе, хозяйство при создании обязательно.

Полей и наблюдений в миграции нет намеренно. Контур — конкретный участок конкретного хозяйства, а спутниковые значения выдумывать нельзя: сервис отделяет измеренное от рассчитанного, и подложенный в базу NDVI превратил бы демонстрацию в подделку.
