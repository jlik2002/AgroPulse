# Отчёты и выгрузки

## Четыре уровня документа

| Уровень | Документ | Адресат |
|---|---|---|
| Поле | аналитический отчёт с выбором разделов | агроном |
| Хозяйство | заключение о состоянии угодий | комиссия |
| Реестр | реестр приоритетной поддержки по проекту | распорядитель средств |
| Проект | сводка по всем полям, очередь на осмотр | руководитель хозяйства |

Отчёт собирается синхронно: генерация занимает секунды, очередь ради неё усложнила бы скачивание без выигрыша. PDF кладётся в объектное хранилище, повторное скачивание его не пересобирает.

Заключение по хозяйству адресуется проектом: справочник общий, и одно предприятие даёт разные заключения за разные периоды. Ключ объекта в хранилище включает проект.

## Разделы отчёта по полю

`summary`, `state`, `dynamics`, `radar`, `anomalies`, `forecast`, `quality`, `table`. По умолчанию включены все, кроме полной таблицы значений: она раздувает документ.

Состав разделов входит в ключ хранения — два отчёта по одному полю с разным набором разделов это разные документы.

Разметку страниц знает только вёрстка PDF, поэтому она приезжает заголовками ответа: `X-Report-Pages` и `X-Report-Sections` с оглавлением вида `state:1,anomalies:3`. Номер раздела и номер страницы — разные величины: раздел занимает и полстраницы, и три.

## Список документов

Сформированный документ регистрируется в базе: заключение живёт дольше момента скачивания, на него ссылаются и его перечитывают. У документа есть владелец, дата и число страниц.

Содержимое в базе не хранится — только ключ объекта в S3.

Повторное скачивание из списка отдаёт сохранённую версию, а не пересобранную: если данные изменились, пересборка дала бы другой документ, и ссылка на «тот самый отчёт» перестала бы значить что-либо.

Отказ хранилища не мешает скачать файл — документ уже собран. Но строки в базе тогда не появляется: она указывала бы на объект, которого нет.

## Выгрузка CSV

Состав колонок по полю закреплён продуктовым требованием и произвольно не меняется: на него могут опираться внешние обработки.

```
field_id, field_name, date, ndvi_mean, ndmi_mean, value_type,
valid_fraction, cloud_fraction, source, temperature, precipitation,
anomaly_level, risk_score, missing_reason
```

Никаких текстов, сгенерированных языковой моделью: только наблюдения, расчёты и признаки качества.

У реестра свой набор колонок — единица строки там другая, хозяйство, а не наблюдение.

Файлы начинаются с метки порядка байтов: без неё Excel открывает кириллицу нечитаемой.

## Роль языковой модели

Модель получает готовые числа и обязана лишь пересказать их. Своих расчётов она не делает.

Каждое число и каждая дата из сгенерированного текста ищутся в исходном JSON. Не нашлось — текст бракуется целиком, а не правится: починка отдельного числа означала бы, что остальному тексту мы доверяем без оснований.

Без ключа OpenRouter считается всё, кроме текстовых пояснений. На их месте в отчёте появляется указание причины.
